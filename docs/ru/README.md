# sub-filter

Умный фильтр подписок на прокси-серверы: **VLESS, VMess, Trojan, Shadowsocks, Hysteria2**
(`vless://`, `vmess://`, `trojan://`, `ss://`, `hysteria2://`, `hy2://`).

Программа проверяет каждую ссылку внутри подписки на:

- **безопасность** (например, блокирует `security=none` в VLESS),
- **корректность** (например, требует `pbk` при `security=reality`),
- наличие **«запрещённых слов»** в названии сервера — по гибким правилам
  (вырезать, заменить или удалить),
- **маркеры страны** во фрагменте ссылки (флаг, название, ISO-код).

Результат — чистая, безопасная подписка, готовая к использованию в Clash,
Sing-Box, роутерах и других клиентах.

> ⚠️ Программа **не проверяет живучесть** прокси — только корректность
> конфигурации. Для проверки доступности используйте
> [xray-checker](https://github.com/kutovoys/xray-checker).

---

## Возможности

- ✅ Валидация по гибким [правилам](FILTER_RULES.md) из `rules.yaml`
- ✅ [Фильтрация «плохих слов»](BADWORDS.md) из `badwords.yaml` (strip / replace / delete)
- ✅ Фильтрация по **одной или нескольким странам** (по умолчанию до 20)
- ✅ Дедупликация с сохранением наиболее полной версии одинаковых серверов
- ✅ Объединение нескольких подписок в одну (`/merge`)
- ✅ Форматы вывода: обычный текст, YAML (Clash/Mihomo), base64 — см. [FORMAT_PARAMETER](FORMAT_PARAMETER.md)
- ✅ Кеширование на диск (по умолчанию 30 минут)
- ✅ Режимы HTTP-сервера и однократной CLI-обработки

Требуется **Go 1.26+** (см. `go.mod`).

```bash
go build -o sub-filter .
```

## Конфигурация

Программа читает один YAML-файл конфигурации. Путь определяется в таком порядке:

1. флаг `--config <путь>`;
2. переменная окружения `SUBFILTER_CONFIG`;
3. `./config/config.yaml` (по умолчанию).

### Вложенный формат

Предпочтительная структура — вложенные секции:

```yaml
server:
  port: 8000                 # HTTP-порт
  host: 0.0.0.0              # адрес привязки
  read_timeout: 10s
  write_timeout: 10s
  idle_timeout: 60s

cache:
  directory: /tmp/sub-filter-cache
  ttl: 30m                   # время актуальности кэша
  max_age: 24h               # жёсткий срок хранения записей кэша
  cleanup_interval: 2m
  merge_buckets: 256         # шарды для потокового merge на диске

sources:
  file: ./config/sub.txt     # URL подписок, по одному на строку
  fetch_timeout: 10s
  max_size: 10485760         # максимальный размер источника, байты (10 МБ)
  max_sources: 1000

validation:
  rules_file: ./config/rules.yaml
  bad_words_file: ./config/badwords.yaml
  countries_file: ./config/countries.yaml
  ua_file: ./config/uagent.txt   # дополнительные шаблоны User-Agent
  max_countries: 20          # максимум кодов стран в запросе
  max_merge_ids: 20          # максимум источников в /merge

logging:
  level: info                # debug, info, warn, error
  format: json               # json или text
```

### Устаревшие плоские ключи

Для обратной совместимости загрузчик также принимает плоские ключи:
`sources_file`, `rules_file`, `bad_words_file`, `countries_file`, `uagent_file`,
`cache_dir`, `cache_ttl`, `max_country_codes`, `max_merge_ids`, `merge_buckets`.
Именно этот плоский формат использует штатный
[`config/config.yaml`](../../config/config.yaml). Вложенные значения имеют
приоритет над плоскими.

### Переменные окружения

| Переменная         | Назначение                                             |
|--------------------|--------------------------------------------------------|
| `SUBFILTER_CONFIG` | Путь к файлу конфигурации                              |
| `SUBFILTER_PORT`   | Переопределяет `server.port`                           |
| `LOG_LEVEL`        | Уровень логирования (`debug`, `info`, `warn`, `error`) |

## Режим 1: HTTP-сервер

Фильтрует подписки «на лету» при каждом запросе.

```bash
./sub-filter [порт]
```

Единственный позиционный аргумент — порт (по умолчанию `8000`). Все остальные
настройки берутся из файла конфигурации.

```bash
# Минимальный запуск (./config/config.yaml, порт 8000)
./sub-filter

# Запуск на другом порту
./sub-filter 8080

# Свой файл конфигурации и подробное логирование
./sub-filter --config ./my-config.yaml --debug
```

### Эндпоинты

| Эндпоинт  | Описание                                             |
|-----------|------------------------------------------------------|
| `/filter` | Фильтрация одной подписки                            |
| `/merge`  | Объединение и фильтрация нескольких подписок         |
| `/health` | Проверка здоровья, возвращает `{"status":"ok", ...}` |

### Параметры запроса

| Параметр | Где работает | Описание                                                                                                                         |
|----------|--------------|----------------------------------------------------------------------------------------------------------------------------------|
| `id`     | `/filter`    | ID источника — номер строки в `sources.file` (с 1, только валидные строки)                                                       |
| `ids`    | `/merge`     | ID источников через запятую или повтором (`ids=1&ids=2`); устаревший `id` также принимается. Максимум `validation.max_merge_ids` |
| `c`      | оба          | Коды стран [ISO 3166-1 alpha-2](https://ru.wikipedia.org/wiki/ISO_3166-1) через запятую. Максимум `validation.max_countries`     |
| `lim`    | оба          | Максимальное количество строк прокси в ответе                                                                                    |
| `format` | оба          | Формат вывода: `yaml`, `base64` или комбинация — см. [FORMAT_PARAMETER](FORMAT_PARAMETER.md)                                     |

**Примеры:**

```text
/filter?id=1                       → фильтрация первой подписки
/filter?id=1&c=DE                  → только серверы Германии
/filter?id=1&format=yaml           → вывод YAML для Clash/Mihomo
/merge?ids=1,2,3&c=US,CA           → объединение трёх источников, серверы США/Канады
/merge?ids=1,2&format=yaml&lim=100 → объединённый YAML, не более 100 строк
```

### Защита запросов

`/filter` и `/merge` защищены (не отключайте без проверки безопасности):

- **Белый список User-Agent.** Запрос принимается, только если его
  `User-Agent` начинается со встроенного префикса (`clash`, `happ`, `incy`)
  или соответствует regex-шаблону из `validation.ua_file`
  (`config/uagent.txt`). Встроенные префиксы сравниваются с учётом регистра,
  поэтому `curl -H "User-Agent: clash" ...` работает, а `Clash` — нет.
  Остальные запросы получают `400 Invalid User-Agent`.
- **Ограничение частоты по IP.** Устойчивая скорость 10 запросов/сек с
  всплеском до 5. Лишние запросы получают `429 Too Many Requests`.
- **Строгая валидация ID источника.** ID должен соответствовать
  `^[a-zA-Z0-9_]+$` и быть не длиннее 64 символов.

## Режим 2: CLI

Обрабатывает подписки один раз и записывает результаты в каталог кэша
(или выводит их в терминал).

```bash
./sub-filter --cli [--stdout] [--config файл.yaml] [--country AD,DE] [--debug] [id ...]
```

| Флаг        | Описание                                                                               |
|-------------|----------------------------------------------------------------------------------------|
| `--cli`     | Запуск в CLI-режиме                                                                    |
| `--stdout`  | Вывод результата в терминал вместо записи в кэш                                        |
| `--config`  | Использовать внешний файл конфигурации                                                 |
| `--country` | Фильтрация по кодам стран (например, `--country=NL,RU`), те же правила, что и для `c=` |
| `--debug`   | Подробная информация при старте и логирование обработки                                |

ID источников можно передать позиционно; если они не указаны, обрабатываются
все настроенные источники.

```bash
# Обработать все источники и сохранить в каталог кэша
./sub-filter --cli

# Вывести результат в терминал
./sub-filter --cli --stdout

# Обработка с фильтрацией по странам
./sub-filter --cli --country=NL,RU

# Обработать только источники 1 и 3 со своим конфигом
./sub-filter --cli --config ./my-config.yaml 1 3
```

## Фильтрация по странам

Данные о странах хранятся в `config/countries.yaml` (плоская карта с ключом —
кодом CCA2):

```yaml
RU:
  cca3: RUS
  flag: '🇷🇺'
  name: Russia
  native: 'Россия|Российская Федерация'
```

При активной фильтрации по странам программа ищет во **фрагменте** (`#...`)
каждой ссылки любые из следующих строк для запрошенных стран:

- **код CCA3**: `RUS`
- **флаг-эмодзи**: `🇷🇺`
- **общее название**: `Russia`
- **национальные названия**: `Россия`, `Российская Федерация`

Сравнение **регистронезависимое** и поддерживает **URL-декодирование**.
Ссылки без фрагмента не проходят фильтр по странам.

> 📝 Двухбуквенный код CCA2 (например, `RU`) используется как ключ запроса, но
> сам по себе во фрагментах не ищется — сопоставление идёт по CCA3, флагу и
> названиям.

## Файлы кэша

Результаты хранятся в `cache.directory` (по умолчанию `/tmp/sub-filter-cache`).

Серверный режим (`/filter`) создаёт для каждой комбинации источника и стран:

| Файл                           | Содержимое                                  |
|--------------------------------|---------------------------------------------|
| `orig_<id>[_c_<КОДЫ>].txt`     | Исходная загруженная подписка               |
| `mod_<id>[_c_<КОДЫ>].txt`      | Отфильтрованный профиль (отдаётся клиентам) |
| `rejected_<id>[_c_<КОДЫ>].txt` | Отклонённые строки с причинами              |

`/merge` записывает `merge_<id1>_<id2>...[_c_<КОДЫ>].txt`.
CLI-режим записывает `<id>[_c_<КОДЫ>].txt`.

`<КОДЫ>` — отсортированный список кодов стран через подчёркивание
(например, `mod_1_c_DE_NL.txt`). Файлы обновляются, когда они старше
`cache.ttl`.

## Подключение клиента

Добавьте в клиент динамическую подписку:

```text
http://ваш-сервер:8000/filter?id=1&c=NL,RU
```

Помните: `User-Agent` клиента должен быть в белом списке (большинство
популярных клиентов уже покрыты `config/uagent.txt`).

> 🔒 **Рекомендация**: используйте за HTTPS reverse proxy (Nginx, Caddy,
> Cloudflare и т.п.).

## Docker

Образ читает конфигурацию из `/config/config.yaml` и слушает порт `8000`
(настраивается через `SUBFILTER_PORT`).

### Запуск сервера

```bash
docker run -d \
  -p 8000:8000 \
  -v $(pwd)/config:/config:ro \
  -v $(pwd)/cache:/tmp/sub-filter-cache \
  ghcr.io/viktor45/sub-filter:latest
```

### CLI в Docker

```bash
# Обработка подписок с записью результата в ./cache
docker run --rm \
  -v $(pwd)/config:/config:ro \
  -v $(pwd)/cache:/tmp/sub-filter-cache \
  ghcr.io/viktor45/sub-filter:latest \
  --cli --country=DE

# Вывод результата в терминал
docker run --rm \
  -v $(pwd)/config:/config:ro \
  ghcr.io/viktor45/sub-filter:latest \
  --cli --stdout
```

В репозитории есть готовые [`docker-compose.yml`](../../docker-compose.yml) и
пример Podman-quadlet [`subfilter.container`](../../subfilter.container).

> 💡 Убедитесь, что каталоги `./config` и `./cache` существуют перед запуском.

## Архитектура

Проект использует модульную архитектуру с внедрением зависимостей:

- **`pkg/config`** — загрузка и валидация конфигурации (YAML, вложенный + плоский форматы)
- **`pkg/service`** — основная бизнес-логика: HTTP-обработчики, фильтрация, merge, кеширование
- **`pkg/errors`** — типизированные ошибки с кодами и severity
- **`pkg/logger`** — структурированное логирование на базе `slog`
- **`pkg/cache`** — кэш скомпилированных regex со статистикой попаданий
- **`internal/validator`** — универсальный движок правил валидации
- **`internal/utils`** — нормализация URL, проверка хостов/портов, справочник стран, дедупликация
- **`vless`, `vmess`, `trojan`, `ss`, `hysteria2`** — парсеры протоколов с общим интерфейсом `ProxyLink`

Как расширять проект — см. [DEVELOPMENT](DEVELOPMENT.md).
