# Часто задаваемые вопросы

## Зачем нужна эта программа?

Подписки на прокси иногда ломаются из-за единственной некорректной строки, и
тогда клиент (на роутере или в приложении) отклоняет всю подписку целиком.
Вместо ручной чистки подписок этот инструмент автоматически удаляет сломанные,
небезопасные или нежелательные серверы. Особенно полезен для роутеров и
устройств с ограниченными ресурсами.

> ⚠️ Программа **не проверяет живучесть** прокси — только корректность
> конфигурации.

## Что именно отклоняет программа?

Со штатным `config/rules.yaml`:

- VLESS с `security=none` (или с отсутствующим `security`, который трактуется
  как `none`), либо без `sni`
- VLESS без `pbk` при `security=reality`, без `serviceName` при `type=grpc`,
  либо без `path` для `ws`/`httpupgrade`/`xhttp`/`splithttp`
- VMess с `security`, равным `none`, `zero` или `null` (без шифрования)
- Trojan с любым параметром `flow` (удалён в Xray-core 2024+)
- Shadowsocks с устаревшими шифрами CFB/CTR
- Hysteria2 без `obfs`/`obfs-password` либо с `insecure=1`/`true`
- Серверы, чьи имена совпадают с правилом `delete` из «плохих слов»
- Серверы, не соответствующие запрошенному списку стран (если фильтр по
  странам включён)
- Ссылки с неподдерживаемыми схемами или некорректные URL

Полный набор правил и способы его настройки — в
[FILTER_RULES](FILTER_RULES.md).

## Зачем фильтровать по странам?

Чтобы использовать только серверы в нужных вам юрисдикциях — например, для
улучшения скорости и стабильности соединения.

## Как работает фильтрация по странам?

Программа сканирует **фрагмент** каждой ссылки прокси (`#...`) на наличие
любой из следующих строк для запрошенных стран:

- код ISO 3166-1 alpha-3: `AND`
- флаг-эмодзи: `🇦🇩`
- общее название: `Andorra`
- национальные названия: `Principat d'Andorra`

Сопоставление **регистронезависимое** и поддерживает **URL-декодирование**.
Двухбуквенный код, который вы передаёте (`c=AD`), выбирает страну, но сам по
себе во фрагменте не ищется. Ссылки без фрагмента не проходят фильтр по
странам.

## Где посмотреть, что было отклонено?

В серверном режиме каталог кэша (по умолчанию `/tmp/sub-filter-cache`)
содержит для каждой комбинации источника и стран:

- `orig_<id>[_c_<КОДЫ>].txt` — исходная загруженная подписка
- `mod_<id>[_c_<КОДЫ>].txt` — отфильтрованный результат
- `rejected_<id>[_c_<КОДЫ>].txt` — отклонённые строки, перед каждой стоит
  строка `# REASON: ...`

`<КОДЫ>` — отсортированные коды стран, соединённые подчёркиванием, например
`rejected_1_c_AD.txt` для `?id=1&c=AD`.

## Почему я получаю «400 Invalid User-Agent»?

`/filter` и `/merge` принимают только запросы, чей `User-Agent` начинается со
встроенного префикса (`clash`, `happ`, `incy`) или соответствует шаблону из
`config/uagent.txt`. Встроенные префиксы сравниваются с учётом регистра,
поэтому с `curl` используйте `User-Agent: clash` (строчными). Большинство
популярных клиентов уже покрыты `uagent.txt`.

## Отправляются ли мои данные куда-либо?

Нет. Вся обработка происходит **локально**. Программа только:

1. Скачивает настроенные вами публичные подписки,
2. Обрабатывает их на вашем устройстве,
3. Передаёт результат вашему клиенту (Clash, роутер и т.п.).

**Никакие данные не отправляются третьим лицам.** Инструмент может работать
как фоновый сервер или в однократном CLI-режиме, не требует облачных сервисов
и может запускаться в Docker-контейнере на вашем собственном устройстве.
