# Правила «плохих слов» (`badwords.yaml`)

Файл [`config/badwords.yaml`](../../config/badwords.yaml) содержит правила
очистки **имён** прокси (фрагментов ссылок), а для `replace` — всей ссылки
целиком. Думайте о нём как о словаре «плохих слов» — не для цензуры, а для
удаления бесполезной, рекламной или опасной информации из имён серверов.

## Что такое «плохое слово»?

Шаблон (слово, фраза или регулярное выражение), который встречается в имени
прокси и нежелателен в итоговом списке. Примеры:

- `[TEST]` — пометка тестового сервера
- `[SPAM]` — явный маркер спама
- `192.168.x.x` — приватный IP, признак ошибки разбора
- `v1.2.3` — номер версии, засоряющий имя

## Структура файла

Файл представляет собой YAML-массив правил:

```yaml
- pattern: "regex для вырезания из имени"
  action: strip

- pattern: "regex, отклоняющий всю строку"
  action: delete

- pattern: "fp=chrome"
  action: replace
  replacement: "fp=firefox"
```

| Поле          | Тип    | Обязательно   | Описание                                       |
|---------------|--------|---------------|------------------------------------------------|
| `pattern`     | строка | ✅ да         | Регулярное выражение (синтаксис Go `regexp`)   |
| `action`      | строка | ✅ да         | `strip`, `delete` или `replace`                |
| `replacement` | строка | для `replace` | Строка замены                                  |
| `comment`     | строка | нет           | Произвольная заметка (программой игнорируется) |

Неизвестное или отсутствующее `action` трактуется как `delete`.

## Действия

### strip

Удаляет совпавшую подстроку из имени; сервер **остаётся** в списке. После
удаления лишние пробелы схлопываются, а имя обрезается по краям.

Используйте для мелкого мусора: версий (`v1.2.3`), пометок test/demo,
рекламных «хвостов».

```yaml
- pattern: '\bv\d+\.\d+(\.\d+)?\b'
  action: strip
```

`"Server v1.2.3 Fast"` → `"Server Fast"` ✅ принят

### delete

Отклоняет **всю строку**; сервер исключается из списка и записывается в
`rejected_*.txt` с указанием сработавшего правила в качестве причины.

Используйте для критичных проблем: маркеров спама/вредоносов, приватных IP,
некорректных портов.

```yaml
- pattern: '(?i)\[(spam|fraud|malware|phishing|scam)\]'
  action: delete
```

`"Server [SPAM] in US"` → ❌ отклонён

### replace

Заменяет совпадение строкой `replacement`; сервер остаётся в списке. В отличие
от `strip`/`delete` (которые работают с декодированным именем), `replace`
применяется ко **всей нормализованной ссылке**, поэтому может исправлять
параметры в любом месте URL.

```yaml
- pattern: "fp=chrome"
  action: replace
  replacement: "fp=firefox"
```

## Где применяются правила

- `strip` и `delete` выполняются против **URL-декодированного фрагмента**
  (части `#имя`) каждой ссылки во время обработки протокола.
- `replace` выполняется против **полной нормализованной ссылки** после
  обработки протокола и до фильтрации по странам.

## Ограничения безопасности

Шаблоны компилируются один раз при старте с защитными ограничениями:

- используется не более **20 шаблонов** (излишек игнорируется с
  предупреждением);
- шаблон длиннее **100 символов** пропускается;
- шаблоны с вложенными квантификаторами, склонные к ReDoS (например,
  `(.*)+`), или с более чем 3 группами захвата отклоняются;
- некорректные регулярные выражения пропускаются (с записью в лог).

## Регулярные выражения

`sub-filter` использует пакет Go `regexp` (синтаксис RE2).

### Экранирование в YAML

Сам YAML интерпретирует обратные слеши в строках с двойными кавычками, поэтому
либо удваивайте их, либо используйте одинарные кавычки:

```yaml
# НЕПРАВИЛЬНО — YAML «съедает» один обратный слеш:
pattern: "\[TEST\]"

# ПРАВИЛЬНО — удвоенные обратные слеши:
pattern: "\\[TEST\\]"

# ПРАВИЛЬНО — одинарные кавычки, без экранирования YAML:
pattern: '\[TEST\]'
```

### Регистронезависимое сопоставление

Добавьте встроенный флаг `(?i)` в начало шаблона:

```yaml
- pattern: '(?i)\[demo\]'   # совпадает с [DEMO], [demo], [Demo]
  action: strip
```

## Практические примеры

Удаление номеров версий:

```yaml
- pattern: '\bv\d+\.\d+(\.\d+)?\b'
  action: strip
```

Удаление пометок demo в любых скобках:

```yaml
- pattern: '(?i)\[demo\]|\(demo\)|<demo>'
  action: strip
```

Отклонение строк с приватными IP (признак ошибки разбора):

```yaml
- pattern: '(?i)(localhost|127\.0\.0\.1|192\.168\.|10\.|172\.1[6-9]\.|172\.2[0-9]\.|172\.3[01]\.)'
  action: delete
```

Отклонение маркеров спама/мошенничества/вредоносов:

```yaml
- pattern: '(?i)\[(spam|fraud|malware|phishing|scam)\]'
  action: delete
```

Отклонение некорректных портов (0 или > 65535):

```yaml
- pattern: ':(?:0|6553[6-9]|655[4-9]\d|65[6-9]\d{2}|6[6-9]\d{3}|[7-9]\d{4}|[1-9]\d{5,})'
  action: delete
```

## Советы по написанию шаблонов

- Используйте границы слов для целых слов: `\btest\b` совпадает с `test`, но
  не с `testing`.
- Экранируйте специальные символы: `\[TEST\]`, `example\.com`.
- Предпочитайте `(?i)` вместо перечисления всех вариантов регистра.
- Группируйте альтернативы: `(?i)(spam|fraud|malware)`.
- Будьте строги с правилами `delete` и осторожны с правилами `strip` —
  слишком широкий шаблон `delete` молча удалит хорошие серверы.
- Выстраивайте правила логично: сначала `strip` (очистка), затем `delete`
  (блокировка).

## Отладка

- Проверяйте шаблоны на [regex101.com](https://regex101.com) с диалектом
  **Go**.
- Запустите `./sub-filter --cli` — если файл разбирается, конфигурация
  загружена; некорректные шаблоны сообщаются в лог и пропускаются.
- Проверьте `rejected_<id>.txt` в каталоге кэша: каждая отклонённая строка
  хранится там вместе с причиной, включая сработавшее правило «плохих слов».
